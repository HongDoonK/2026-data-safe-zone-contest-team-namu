## 4. 분석의 우선순위와 중단 규칙

### 4.1 반드시 끝내야 하는 핵심

1. **자료 의미 확인:** 급식카드 코드, 행 한 줄의 의미, 승인·취소 상태, 실제 기간, 현재 등록정보의 기준일을 확인한다.
2. **공표 가능성 확인:** 지역×시간 결과가 최소한 어느 크기에서 반출 가능한지 실제 기준과 데이터로 확인한다.
3. **기본 프로파일:** 지급수단별 시간 분포와 지역 분포를 보여주되 “왜 적은지”는 단정하지 않는다.
4. **등록과 활동의 분리:** 현재 급식등록 비중, 전체 플랫폼 관측 활동, 급식카드 결제 흔적을 서로 다른 열과 그림으로 보여준다.
5. **현장 확인 우선순위표:** 모집 수가 아니라, 어느 지역·시간에서 무엇을 누구에게 확인해야 하는지 정리한다.
6. **공표·반출 안전장치:** 0, 미관측, 자료 미제공, 기준 미달 억제를 구분하고 가명 ID·개별 가맹점은 내보내지 않는다.
7. **재현 증빙:** 입력 목록, 실행 순서, 변환 기록, 품질표, 표·그림 생성 과정을 코드로 다시 돌릴 수 있게 남긴다.

### 4.2 선택 분석 H3·H4·H5의 수행·보류 조건

선택 분석은 핵심 산출물이 완성될 때만 추가한다. 결과가 흥미로워 보인다는 이유로 조건을 낮추지 않는다.

| 분석 | 쉬운 설명 | 수행 조건 | 보류 조건 | 허용되는 결론 |
|---|---|---|---|---|
| **H3 배송 지표 비교** | 같은 가게에서 급식카드와 다른 결제 주문의 배송 기록을 비교 | 주문·결제·배달의 후보 연결과 재사용 0건을 확인하고, 모호·미결합 규모를 공개할 수 있으며, 양 결제수단이 있는 같은 가게의 비교 가능한 배달 주문이 남고, 완료·취소·상태불명의 분모가 분리될 때 | 주문번호 부재로 동일 거래 연결의 신뢰가 낮거나, 비교 가능한 같은 가게가 부족하거나, 포장·배달·상태가 섞이거나, 결과 관측 여부가 결제수단별로 크게 다를 때 | 조정 전후의 **관측된 차이**. 거리·목적지가 없으므로 차별·원인·정책 효과는 말하지 않음 |
| **H4 가맹점 상태 분석** | 급식등록 가맹점의 상태 변화를 시간에 따라 비교 | 급식등록 시작·변경 이력, 가맹점 진입, 폐업 또는 서비스 이탈의 사건 시점, 위험집합 보존 여부가 확인되고 등록 이전 기간으로 비교조건을 만들 수 있을 때 | 현재 스냅샷만 있거나 폐업자 행이 빠졌거나 사건 시점이 없거나 현재 Y를 과거에 붙여야만 분석이 될 때 | 확인된 기간 안의 상태 변화 비교. 참여 효과나 급식등록 때문에 폐업했다는 결론은 금지 |
| **H5 금액 분포 진단** | 급식카드 결제금액이 특정 금액대에 모이는지 확인 | 공식 공고에서 단가·적용기간·적용대상·한도 단위를 확인하고, 제공기관 설명으로 `TOT_AMT`, `CARD_APP_AMT`, 할인, 배달료, 복합결제 관계를 확인할 때 | 주문당 한도인지 불명확하거나 금액 항목 관계가 확인되지 않거나 전후 비교기간이 유효하지 않을 때 | 조건이 완전하면 금액대 집중의 기술적 진단. 조건이 일부면 히스토그램만, 정책 효과는 말하지 않음 |

**선택 분석 중단 순서:** 일정이나 반출이 늦으면 **H3 → H5 → H4** 순으로 새 작업을 중단한다. 다만 H4는 이력이 없으면 일정과 무관하게 즉시 보류한다. 핵심 품질 확인과 공표 검증은 줄이지 않는다.

### 4.3 같은 T2 안에서의 축소 경로

```text
자료 의미와 기간 확인
  ├─ 확인됨 → 공표 가능한 지역·시간 단위 확인
  │            ├─ 행정동×3시간 가능 → 기본 활동 지도와 확인표
  │            ├─ 너무 얇음 → 더 큰 시간대 → 구·군 → 전체기간 순으로 합침
  │            └─ 모두 불가 → 지도 보류, 대구 전체 프로파일과 데이터 가용성 진단
  └─ 등록 이력 없음 → 현재 등록 현황과 과거 활동을 절대 합치지 않고 별도 제시

엄격한 거래 연결 가능 → H3 조건부 수행
등록·폐업 이력 가능   → H4 조건부 수행
제도·금액 의미 확인   → H5 조건부 수행
```

급식카드 관측 건수가 적더라도 이를 지원 실패로 바꾸어 말하지 않는다. 큰 지역·긴 기간으로 합쳐도 공표가 불가능하거나 급식카드 코드 자체의 의미가 확인되지 않으면, **T2의 데이터 가용성·등록 대비 관측 활동 진단까지만 제출 가능성을 검토**한다. 다른 주제로 자동 전환하지 않는다.

## W0 — 준비와 예약을 잠그는 주

**목표:** 데이터를 보기 전에 바깥에서 끝낼 수 있는 준비를 마치고, 첫 방문과 반출 일정을 불확실성 목록으로 관리한다.

### 할 일과 순서

1. 운영·일정 담당이 공식 공지에서 마감, 제출 형식, 방문 인정 단위, 미개방데이터 연계 적격기준을 재확인한다.
2. 방문 가능한 센터와 가장 빠른 날짜를 확인하고 예약을 신청한다. 복수 센터 방문일 합산 여부는 별도 질문으로 남긴다.
3. 반출 신청 양식, 금지 항목, 보완 억제 요구, 평균 심사기간, 재신청 절차를 문의한다.
4. 분석환경의 메모리·저장공간·Python 버전·설치 가능 도구·외부 파일 반입 방식을 확인한다.
5. 데이터 담당이 정의서 컬럼만 사용한 빈 스키마와 품질 점검표를 만든다. 실제 값이나 건수는 만들지 않는다.
6. 분석·검증 담당이 “말할 수 있는 주장 / 말할 수 없는 주장” 표와 H3·H4·H5 허용표를 팀 검토용으로 고정한다.
7. 지도·문서 담당이 공개 행정코드, 행정동-법정동 관계표, 대구 경계, 공개 아동인구의 출처·기준일·공표단위를 목록화한다. 실제 다운로드·가공 시 이용조건을 기록한다.
8. 보안·품질 담당이 반출용 기본 단위를 **행정동×요일×3시간**으로 임시 설정하되, 실제 승인 기준이 더 크면 즉시 상향하도록 규칙을 적는다.

## 7. 품질·반출·재현성 공통 완료 기준

모든 주에 아래 기준을 적용한다.

### 자료와 분석

- 원본 행 수, 기간, 결측, 범주, 키, 참조율을 실행 로그에 남긴다.
- 중복처럼 보이는 행을 제공기관 설명 없이 삭제하지 않는다.
- 기간이 다른 자료를 한 시점의 순위처럼 합치지 않는다.
- 미연결 지역을 0으로 바꾸지 않는다.
- 결과 방향을 본 뒤 집계단위·기간·임계값을 유리하게 바꾸지 않는다.

### 공표와 보안

- 셀의 거래·가게·계정 최소 기준과 보완 억제를 실제 센터 규칙에 맞춰 자동 적용한다.

- 여러 표·지도 사이의 차이로 억제값을 역산할 수 있는지 묶음 단위로 검사한다.
- 승인받지 않은 결과를 기획서에 넣지 않는다.

### 재현성과 문서

- 코드는 번호 순서로 실행되며 각 단계의 입력·출력·파라미터·환경을 기록한다.
- 원본→파생변수 변환표를 코드 주석이 아닌 별도 로그로 남긴다.
- 표·그림마다 실행 파일, 입력 버전, 산출일, 해시를 연결한다.
- 수행하지 않은 분석, 확인되지 않은 수치, 미확정 제도 사실을 완료형으로 쓰지 않는다.

## 9. 사용자 결정이 필요한 사항

1. **팀 인원과 역할 가능 시간:** 총 인원, 주당 가능한 인일, 지도·문서·코드 경험 분포
2. **첫 방문 가능일과 희망 센터:** 9/16까지 가능한지, 대체일은 언제인지
3. **예약·반출 안내를 이미 받은 것이 있는지:** 있으면 이 문서의 계획용 대기 가정을 실제 값으로 교체
4. **내부 우선순위:** 경쟁력보다 안전한 완주를 우선할지, 핵심 완성 뒤 H3 하나에만 추가 투자할지

사용자 답이 오기 전의 기본 선택은 **핵심 완성 우선, H3·H4·H5는 조건부**다.
