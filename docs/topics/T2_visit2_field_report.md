## 1. K1 — 급식카드 정의

- 셀 6 후보 비교: `complete` 0/25, **`dedup` 25/25**, `net_cancel` 0/25, `amt_pos` 0/25, `dest=앱결제` 0/25 (DEST_PAY_GBN은 '앱결제' 하나뿐)
- 월별 차이(완료 − 1차)는 1·2·7·8월에 몰림, 음수 달 없음
- **1차 반출물의 정의 = 완료 + 완전 동일 행 제거.** 결과 문서 §1의 "필터 정의 미기록"이 해소된다.
- 2차 반출물(M2)은 **완료, 중복 제거 안 함**으로 만들었다 → D-012.

## 2. CHILD_DISC_AMT `[잠정 — 재확인 필요]`

- 급식 행 전체(369,750)의 분포가 보고됐다: 25% 1,500 / 50% 2,500 / 최대 33,000. **대부분 0이 아니다** — 현장 메모의 "0이 아닌 행 거의 없음"과 모순.
- 보고된 75% 값 7,500은 평균 2,473·표준편차 1,483과 양립하기 어렵다 → 전사 오류 추정. 3차 방문에서 재확인.
- 해석 후보 `[INFERRED]`: 결제액 중 급식카드 지원분. `TOT_AMT`·`CARD_APP_AMT`와의 관계를 3차에서 확인하면 레드팀 R07(단가 상한 전제)의 검증 재료가 된다.

## 3. K3 — 등록 정보(`CHILD_ABLE_YN`) 사용 방식

- 현재 N인데 기간 중 급식결제가 있던 가게 1,497곳 → **대부분 폐업**
- 등록 Y인데 결제가 한 번도 없던 가게 1,670곳 → **대부분 폐업**
- 등록 N·결제 있음·급식결제 없음 3,383곳 = 급식을 받지 않는 일반 영업 가게
- **결정**: 공급 지표를 둘로 둔다 — ① 현재 등록(Y): 현재 현황 기술용 ② **관측 수용**: 기간 중 급식결제 1건 이상. 과거 공급·시계열은 ②만 쓴다. 확인표(U2)는 **폐업 가게를 먼저 제외**하고 판정한다.
- 미확인: 1,497·1,670 중 "계속사업자(01) + 서비스 유지(N)"의 규모(현장 보고에서 선택 누락). 이 소수가 확인표의 실제 대상이다 → 반출물 또는 3차에서 확인.
