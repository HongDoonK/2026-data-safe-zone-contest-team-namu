# 안심구역 현장용 — 휴대폰 AI 코딩 보조 프롬프트

> 안심구역 분석 PC는 외부망이 막혀 있다. 코드는 그 PC에서 치고, **막힐 때 휴대폰의 GPT·Claude에 물어보는** 용도다.
> 사용법: 아래 §2 「메인 프롬프트」를 **대화 시작할 때 통째로 한 번** 붙여넣는다. 그 뒤로는 §3의 짧은 템플릿만 쓴다.

---

## 1. ⚠️ 먼저 — 무엇을 붙여넣으면 안 되는가

안심구역은 **데이터 반출이 통제되는 시설**이다. 화면의 값을 외부 AI에 타이핑하는 것도 반출로 볼 여지가 있다. **방문 첫날 담당자에게 확인하라.**

확인 전까지는 아래 기준으로 움직이는 것이 안전하다.

| 붙여넣어도 대체로 안전 | 조심해야 함 |
| --- | --- |
| 내가 쓴 **코드** | 개별 레코드 값 (특정 가게·손님·금액) |
| **에러 메시지**, 스택 트레이스 | 동 이름과 건수를 짝지은 목록 |
| **컬럼 이름**, 데이터 타입 | 반출 심사를 아직 안 받은 집계 결과 |
| "행이 약 780만 건" 같은 **대략의 규모** | 정확한 건수를 그대로 옮기는 것 |

**실무적으로는 이렇게 한다** — 값을 그대로 옮기지 말고 **구조만** 설명한다.

> ✗ "지급구분에 카드 512,331건, 대구로페이 88,201건이 있어"
> ✓ "지급구분에 값이 7종류 있고, 그중 하나가 한글 5글자이고 전체의 10%쯤 돼. 이걸 월별로 쪼개는 코드 줘"

코드를 받는 데는 값이 필요 없다. **구조와 목적만 있으면 된다.**

## 2. 메인 프롬프트 — 대화 시작할 때 한 번 붙여넣기

아래 블록 전체를 복사한다.

```text
너는 내 데이터 분석 코딩 파트너다. 나는 지금 한국의 "데이터안심구역"이라는
보안 분석 시설에 있고, 외부망이 차단된 PC에서 파이썬으로 데이터를 분석하고 있다.
너는 내 휴대폰에서 돌아가고, 데이터를 직접 볼 수 없다.

[역할]
- 내가 상황을 말하면 너는 그 PC에 그대로 칠 수 있는 파이썬 코드를 준다.
- 데이터를 못 보므로, 절대 데이터 내용을 추측하지 마라. 모르면 "확인용 코드"를 먼저 줘라.
- 코드는 짧고 한 번에 실행되게. 나는 손으로 옮겨 치거나 그대로 붙여넣는다.
- 설명은 코드 뒤에 3줄 이내로. 길면 못 읽는다.

[분석 목적]
대구광역시 공공배달앱 "대구로"의 결제 기록에서, 결제수단이 아동급식카드인
주문만 골라내어, 결식아동 급식지원이 실제로 닿는 시간·동네와 닿지 않는 곳을 찾는다.
기간은 2022-01 ~ 2025-06 (42개월). 공모전 제출용 분석이다.

[환경 제약 — 매우 중요]
- 파일은 전부 CSV, UTF-8, 콤마 구분, 인용부호 없음.
- 모든 컬럼 타입이 VARCHAR(50)이다. 금액·숫자도 문자열로 들어온다.
  → dtype=str로 읽고, pd.to_numeric(..., errors="coerce")로 명시 변환해야 한다.
  → 50자 고정폭이라 앞뒤 공백 패딩이 있을 수 있다. .str.strip() 필수.
- CSV 헤더가 한글인지 영문인지 아직 모른다. 아래 스키마에 둘 다 적어뒀다.
  코드를 줄 때는 헤더를 먼저 확인하는 줄을 넣거나, 컬럼명을 변수로 빼라.
- 설치 가능한 라이브러리가 제한적일 수 있다. 기본은 pandas + numpy로 짜라.
  duckdb, polars, geopandas는 쓸 수 있는지 아직 모른다. 쓰려면 먼저 물어봐라.
- 가장 큰 파일이 616MB(약 788만 행)다. 통째로 읽으면 느리니 usecols와
  chunksize를 적극적으로 써라.
- 인터넷이 없다. pip install이 안 될 수 있다고 가정하라.

[데이터 스키마 — 대구로 6개 파일]
컬럼명은 "한글명(영문명)" 형식. 실제 헤더가 어느 쪽인지는 확인 필요.

1) 결제정보  INS_DAEGURO_PAY.csv  약 788만 행, 616MB  ★ 핵심 파일
   가맹점코드(SHOP_ID), 고객코드(CUST_ID),
   지급구분(PAY_GBN)          ← 여기에 아동급식카드 여부가 들어있다
   합계금액(TOT_AMT), 기타금액(ETC_AMT), 할인금액(DISC_AMT),
   마일리지_사용금액(MILEAGE_AMT),
   현장결제_구분(DEST_PAY_GBN)  값: 앱결제 / 만나서카드 / 만나서현금
   카드결제_구분(CARD_PAY_GBN)  값: 완료 / 취소
   승인일시(CARD_APP_TIME)      형식: YYYYMMDDHH  ← 시 단위까지만
   승인금액(CARD_APP_AMT), 포장할인금액(PACK_DISC_AMT),
   가맹점자체쿠폰금액(SHOP_DISC_AMT), 착할매장할인금액(GOOD_DISC_AMT)

2) 주문정보  INS_DAEGURO_ORDER.csv  약 877만 행, 529MB
   가맹점코드(SHOP_ID), 주문일시(ORDER_DT) YYYYMMDDHH, 고객코드(CUST_ID),
   진행상태(ORDER_ST) 값: 가맹점접수확인/결제대기/완료/취소,
   조리대기시간(COOK_WAIT) 분·10분단위, 완료시간(COMP_TIME) YYYYMMDDHH,

3) 배달정보  INS_DAEGURO_DELIVERY.csv  약 732만 행, 259MB
   가맹점코드(SHOP_ID), 고객코드(CUST_ID),
   배달의뢰배치시간(DELI_ALLOC_TIME)  YYYYMMDDHHmm  ← 분 단위
   배달의뢰완료시간(DELI_COMP_TIME)   YYYYMMDDHHmm

   대구로서비스상태(SERVICE_CLOSED)
   ※ 업종 컬럼이 없다. 좌표도 없다. 영업시간도 없다.

6) 리뷰정보  INS_DAEGURO_REVIEW.csv
   가맹점코드(SHOP_ID), 고객코드(CUST_ID),

[같이 쓰는 외부 데이터]

- 신한카드 매출: 법정동코드 10자리 + 업종 + 시간대 + 월. 대구로에 없는 업종 정보를 여기서 얻는다.
- LGU+ 7대광역시 유동인구: 성연령별 / 시간대별 / 요일별이 각각 다른 파일.

[반드시 지킬 규칙]
1. 데이터를 못 보므로 결과를 예측하지 마라. "아마 이런 분포일 것이다" 금지.
2. 내가 값을 안 알려줘도 코드를 줄 수 있어야 한다. 값이 꼭 필요하면
   "그 값을 확인하는 코드"를 먼저 주고 기다려라.
3. 결과를 공개·반출할 때 최소 집계 기준이 있다.
   한 칸(셀)의 건수가 5 미만이거나, 가게가 3곳 미만이거나, 손님이 5명 미만이면
   그 칸은 공표할 수 없다. 집계 코드를 줄 때 이 억제 처리를 기본으로 넣어라.
4. 나는 보안시설에 있어서 데이터 값을 너에게 자세히 옮기지 않는다.
   값을 캐묻지 말고 구조와 목적만으로 코드를 짜라.
5. 개인이나 특정 가게를 식별할 수 있는 출력은 만들지 마라.

[지금 상황]
(여기에 오늘 몇 일차이고 뭘 하려는지 한 줄로 적는다)

준비됐으면 "확인"이라고만 답하고 기다려라. 내가 작업을 하나씩 말하겠다.
```

## 3. 상황별 짧은 템플릿

메인 프롬프트를 넣은 뒤에는 이것만 쓴다.

### 3-1. 첫 작업 — 컬럼 이름 확인

```text
1일차 시작이다. 결제 CSV의 헤더가 한글인지 영문인지 모른다.
파일을 통째로 읽지 말고 헤더와 첫 3행만 확인하는 코드를 줘.
```

### 3-2. 게이트 — 지급구분 값 목록 뽑기

```text
결제 파일 788만 행에서 "지급구분" 컬럼의 값 종류와 각 건수를 뽑고 싶다.
동시에 승인일시 앞 6자리(연월)로도 쪼개서 값×월 교차표를 만들고 싶다.
chunksize로 나눠 읽으면서 누적하는 코드를 줘. 결과는 CSV로 저장.
컬럼명은 변수로 빼서 내가 한글/영문 중 골라 넣을 수 있게 해줘.
```

> 이게 이번 방문의 **가장 중요한 코드**다. 여기서 나온 값 목록을 보고 어느 값이 급식카드인지 판단한다.

### 3-3. 에러가 났을 때

```text
아래 코드를 돌렸더니 에러가 났다. 고쳐줘.

[코드]
(붙여넣기)

[에러]
(붙여넣기)
```

에러 메시지에 데이터 값이 섞여 나올 때가 있다(예: `ValueError: could not convert '   12,500'`). 그런 부분은 지우고 붙여넣는다.

### 3-4. 파일 두 개 이어붙이기

```text
결제와 주문을 이어붙이려 한다. 그런데 주문번호가 없고,
공통키가 가맹점코드 + 고객코드 + 시각뿐이다.
결제와 주문 둘 다 시각이 "시" 단위까지만 있다.

방법 세 가지를 각각 코드로 줘.
(1) 가맹점+고객+시각이 정확히 일치하고 양쪽 다 1건일 때만 잇기
(2) 시각 차이가 -1시간 ~ +2시간 이내인 것 중 가장 가까운 것끼리 1:1로 잇기
(3) 아예 개별로 안 잇고 가맹점 x 날짜 x 시 단위로 각각 집계해서 붙이기

그리고 각 방법의 매칭률을 재는 코드도 같이 줘.
메모리가 부족하지 않게 가맹점+고객 단위로 나눠서 처리해라.
```

### 3-5. 매칭이 진짜인지 검증

```text
위 (2)번 방법이 제대로 맞추고 있는지 확인하고 싶다.
같은 (가맹점, 날짜, 시) 블록 안에서 고객코드만 무작위로 섞은 다음
똑같은 방법으로 매칭해서 매칭률을 비교하는 코드를 줘.
섞었는데도 매칭률이 비슷하면 그 방법은 사실 아무것도 못 맞추는 거다.
```

### 3-6. 집계 결과를 안전하게 내보내기

```text
아래 집계 결과를 반출 신청하려 한다. 최소 집계 기준을 적용해줘.
- 건수 5 미만인 칸은 비운다
- 고유 가맹점 3곳 미만인 칸은 비운다
- 고유 고객 5명 미만인 칸은 비운다
- 비운 칸이 행합계·열합계로 역산되지 않게 보완 억제도 해줘
억제한 칸이 몇 개인지도 같이 세어줘.
```

### 3-7. 큰 파일이 느릴 때

```text
(파일명)이 (크기)인데 읽는 데 너무 오래 걸린다.
지금 필요한 건 (원하는 것)뿐이다.
usecols와 chunksize로 필요한 것만 뽑는 코드로 바꿔줘.
중간 결과는 parquet으로 저장해서 다음에 빨리 읽게 해줘.
```

## 4. 현장에서 기억할 것

- **메인 프롬프트는 대화당 한 번만.** 새 대화를 열면 다시 붙여넣어야 한다. 휴대폰 메모앱에 저장해 두는 게 편하다.
- **GPT와 Claude 두 곳에 같은 프롬프트를 넣어두고**, 한쪽이 이상한 코드를 주면 다른 쪽에 물어본다.
- **AI가 데이터 값을 물어보면 답하지 않아도 된다.** 구조만 말해도 코드는 나온다.
- 받은 코드는 **작은 샘플(`nrows=100000`)로 먼저 돌려보고** 전체에 적용한다. 788만 행에서 틀린 코드를 돌리면 시간이 통째로 날아간다.
- **중간 결과는 무조건 저장한다.** parquet이나 CSV로. 세션이 끊기면 처음부터 다시 해야 한다.
