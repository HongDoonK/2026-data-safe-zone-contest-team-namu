## 0. 당신에게 요청하는 것

우리 팀이 대회에 제출할 분석 주제 하나가 있다. 설계는 끝났고 실행 직전이다.

**당신의 일은 이 주제를 무너뜨리려 시도한 뒤, 무너지지 않는 부분에 대해서는 방어 논리를 만들어 주는 것이다.**

우리는 칭찬을 원하지 않는다. 심사위원이 발표장에서 던질 가장 아픈 질문을 미리 맞고 싶다. 본선 평가에 "질의응답 대응"이 명시적 배점 항목으로 들어가 있다.

## 2. 배경 요약

- **대회**: 데이터안심구역 미개방데이터 활용 경진대회. 예선(서면·기술평가 100점) → 본선(발표 100점).
- **주제**: 공공배달앱 '대구로'의 결제 로그에서 결제수단이 '아동급식카드'인 거래를 식별해, 결식아동 급식지원이 실제로 닿는 시공간과 닿지 않는 곳을 분석한다.
- **현 상태**: **실제 데이터는 아직 없다.** 우리가 가진 것은 데이터 정의서뿐이다. 안심구역을 방문해야 데이터를 볼 수 있고, 첫 방문일이 아직 오지 않았다.
- **선정은 끝났다**: 28개 후보를 평가해 이 주제가 최종 2순위로 확정됐다. **주제를 바꾸라는 제안은 요청 범위 밖이다.**

## 3. 절대 규칙

이것을 어기면 결과물이 쓸모없어진다.

1. **데이터 분포·분석 결과·모델 성능을 추정하지 마라.** 특히 "아동급식카드 결제가 대략 몇 건일 것이다" 같은 추정을 하지 마라. 우리는 그 숫자를 모르고, 당신도 모른다. 그것이 이 주제의 핵심 리스크다.
2. **표기를 지켜라.** `[CONFIRMED]` 정의서·요강에 명시 / `[INFERRED]` 구조로부터의 추정 / `[VERIFY_WITH_DATA]` 실데이터 필요 / `[ASK]` 사무국 문의 필요.
3. **주제 선정을 재론하지 마라.** "다른 주제가 낫다"는 결론은 채택되지 않는다.
4. **`docs/` 하위 기존 파일을 수정하지 마라.** 새 파일만 만들어라.
5. **한국 아동급식 제도에 대한 사실을 단정하지 마라.** 단가, 지원 대상 규모, 배달앱 결제 허용 시점 등은 우리가 공개자료로 확인할 항목이다. 당신이 아는 것으로 채우지 말고 **"확인 필요"로 표시**하라.
6. **일반론을 쓰지 마라.** "표본이 편향될 수 있다" 같은 문장은 가치가 없다. **이 데이터의 이 컬럼 때문에 이 가설의 이 계수가 이렇게 틀어진다**는 수준으로 구체적이어야 한다.

## 4. 작업 절차 — 3단계

### Phase 1 — 독립 공격 (봉인 파일을 열기 전에 수행)

같은 폴더에 `T2_redteam_sealed_list.md`가 있다. **Phase 1 결과물을 다 쓰기 전에는 그 파일을 열지 마라.** 우리가 이미 알고 있는 문제 목록이 들어 있어서, 먼저 보면 당신의 시야가 그것에 갇힌다.

당신 스스로 이 주제를 공격하라. 다음 6개 축을 모두 훑되, 축마다 억지로 만들어내지는 마라. 진짜 문제만 적어라.

| 공격 축 | 물어야 할 것 |
| --- | --- |
| **독창성** | 이 발견이 정말 새로운가? 이미 알려진 사실을 비싼 데이터로 재확인하는 것은 아닌가? 2025 수상작과 실질적으로 겹치지 않는가? |
| **필연성** | 미개방데이터가 정말 있어야 하는가? 공개데이터로 80%를 할 수 있다면 이 주제는 약하다 |
| **논리** | 결론이 전제로부터 나오는가? 관측하는 것과 주장하는 것 사이에 도약이 있는가? |
| **식별** | 인과·비교 주장이 성립하는가? 관측되지 않는 교란변수 중 처치·결과와 **동시에** 상관된 것이 있는가? 순환논리·데이터 누수는 없는가? |
| **실행** | 6주 안에 30p로 끝나는가? 설계가 과적재는 아닌가? 게이트 실패 시 대응이 실제로 작동하는가? |
| **효용** | 결과를 알면 누가 무엇을 다르게 하는가? 제안된 정책 레버가 실재하는가? |

**Phase 1 출력 요건**

- 문제를 **심각도 순으로 정렬**하라. "치명적 / 중대 / 보완 필요" 3등급.
- 각 문제마다 **어떤 파일의 어느 절·어느 컬럼이 근거인지** 적어라.
- **가장 아픈 것 하나를 명시하라.** "심사위원이 딱 하나만 물을 수 있다면 이것을 물을 것이다."

### Phase 2 — 대조

이제 `T2_redteam_sealed_list.md`를 열어라. 우리가 이미 파악한 문제 목록이다.

- **당신이 찾았지만 목록에 없는 것** → 이게 이번 검토의 진짜 수확이다. 별도로 강조하라.
- **목록에 있지만 당신이 못 찾은 것** → 왜 놓쳤는지 한 줄로 적어라. 우리 설계 문서가 그 문제를 잘 가리고 있다는 뜻일 수 있고, 그건 그것대로 위험 신호다.
- **양쪽에 다 있는 것** → 심각도 판단이 일치하는지 비교하라. 우리가 과소평가한 것이 있는가?

### Phase 3 — 방어 설계

Phase 1·2에서 확정된 문제 전부에 대해 방어를 설계하라. **모든 문제를 방어할 수 있는 척하지 마라.** 다음 4개 중 하나로 분류하라.

| 분류 | 의미 | 요구 산출물 |
| --- | --- | --- |
| **A. 완전 방어** | 반박이 사실관계에서 틀렸거나, 설계가 이미 처리하고 있다 | 발표에서 그대로 말할 **2~3문장 반박문** |
| **B. 부분 방어** | 문제는 실재하나 영향을 제한할 수 있다 | **구체적 설계 변경** — 어떤 분석을 추가·교체할지, 어떤 표·그림으로 보일지 |
| **C. 방어 불가 → 설계 변경 필수** | 지금 설계로는 못 막는다. 분석을 바꿔야 한다 | **대안 설계**와 그것이 일정·배점에 미치는 영향 |
| **D. 방어 불가 → 한계로 명시** | 데이터의 구조적 한계라 못 고친다 | 기획서에 그대로 넣을 **한계 서술 문구**. 방어 대신 정직함으로 신뢰를 얻는 문장 |

**D를 두려워하지 마라.** 한계를 먼저 말하는 팀이 질의응답에서 강하다. 다만 D가 너무 많으면 주제가 위험하다는 신호이므로, **D의 총합이 주제를 무너뜨리는 수준인지 마지막에 판정하라.**

**Phase 3 추가 요구**

1. **예상 질의응답 10개.** 심사위원이 실제로 던질 법한 질문과 30초 안에 끝나는 답변. 가장 아픈 순서로.
2. **한 장 방어 카드.** 발표 백업 슬라이드용. 공격 → 답변 1줄 형태의 표.
3. **설계 변경 요약.** B·C에서 나온 변경사항을 우선순위와 소요 시간과 함께 목록화. 6주 일정에 실제로 들어가는지 판단하라.

## 5. 특별히 봐 달라는 지점

우리가 스스로 불안한 곳이다. 여기를 특히 세게 때려라.

1. **게이트 임계값의 근거.** `T2_child_meal_card.md` §4.2에서 10만 / 2만 / 2천이라는 숫자를 "필요 표본에서 역산"했다고 주장한다. **역산이 타당한가?** 셀 수 계산, EPV 가정, 결합 손실 30% 가정이 자의적이지 않은가?
2. **DCAI 지수가 진짜 지수인가.** §3.1의 구성이 자의적 조합은 아닌가? 구성요소의 가중치 근거가 있는가? 지수가 무엇을 재고 있는지 한 문장으로 말할 수 있는가?
3. **H3의 식별.** §3.3. 가맹점 고정효과 + 성향점수 매칭으로 충분한가? **처치와 결과에 동시에 걸리는 미관측 변수를 하나라도 더 찾아내면 그것이 이번 검토의 최대 성과다.**
4. **매개분석을 매개분석이라 부를 수 있는가.** §3.3.2. 배달팁은 주문과 동시에 결정되는 소비자 선택이다. 이것을 매개변수로 두는 것이 정당한가?
5. **산출물과 수상 패턴의 정합.** `COMPETITION_RULES.md` §7.2는 수상작이 "지수·지도·최적입지·솔루션" 형태이며 "순수 학술적 인과추론·계량경제 분석 형태의 수상작은 확인되지 않는다"고 적었다. **그런데 우리 설계의 무게중심은 계량경제 쪽이다.** 이 모순을 어떻게 볼 것인가?
6. **연계 점수와 기간 불일치.** §5.3의 3층 구조가 심사위원에게 "연계의 완성도"로 보일까, "기간이 안 맞는 데이터를 억지로 붙였다"로 보일까?
7. **윤리 프레임의 역설.** §7.1은 "아동에 대해 어떤 주장도 하지 않는다"고 선언한다. 그런데 주제 제목과 문제 정의는 "결식아동 급식지원"이다. **아동에 대해 말하지 않으면서 아동 정책을 제언할 수 있는가?** 이 긴장을 어떻게 해소하는가?

## 6. 출력 형식

**하나의 마크다운 파일**로 작성해 `docs/topics/T2_redteam_report.md`에 저장하라.

```text
# T2 레드팀 보고서

## 0. 총평
   - 이 주제는 살아남는가? (생존 / 조건부 생존 / 재설계 필요)
   - 가장 아픈 공격 하나
   - 방어 후 남는 잔여 위험

## 1. Phase 1 — 독립 공격
   ### 1.1 치명적
   ### 1.2 중대
   ### 1.3 보완 필요
   (각 항목: 공격 / 근거 파일·절·컬럼 / 왜 아픈가)

## 2. Phase 2 — 봉인 목록과의 대조
   ### 2.1 새로 발견한 것        ← 가장 중요
   ### 2.2 놓친 것과 그 이유
   ### 2.3 심각도 판단이 갈린 것

## 3. Phase 3 — 방어 설계
   ### 3.1 완전 방어 (A)
   ### 3.2 부분 방어 (B) — 설계 변경 포함
   ### 3.3 설계 변경 필수 (C)
   ### 3.4 한계로 명시 (D) — 기획서 문구 포함
   ### 3.5 D의 총합 판정

## 4. 예상 질의응답 10선

## 5. 한 장 방어 카드

## 6. 설계 변경 요약 (우선순위 · 소요시간 · 6주 일정 적합성)

## 7. 미해결 — 우리도 답을 모르는 것
```

**분량**: 필요한 만큼. 다만 문장마다 근거가 있어야 한다. 길이로 승부하지 마라.

**어조**: 적대적이되 정직하게. 우리를 이기려 하지 말고, **심사위원보다 먼저 때려라.**

## 7. 마지막

이 주제의 진짜 값어치는 "게이트를 통과하면 아주 강하고, 통과 못 하면 무너진다"는 데 있다. 우리는 그 게이트를 이미 알고 있다.

**당신이 찾아야 할 것은 우리가 모르는 두 번째 게이트다.**
