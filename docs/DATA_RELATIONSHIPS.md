# DATA_RELATIONSHIPS.md — 데이터셋 간 연결 가능성 (초안)

> 표기 규칙은 [DATA_CATALOG.md](DATA_CATALOG.md)와 동일: `[CONFIRMED]` 정의서에 명시 / `[INFERRED]` 구조상 추정 / `[VERIFY_WITH_DATA]` 실데이터 필요.
> **이 문서는 "join이 가능하다"를 확정하지 않는다.** 후보 key와 확인해야 할 사항만 정리한다.

---

## 1. 핵심 연결축 4가지

### 축 1 — 행정구역 코드 (가장 강력한 후보 축)
법정동코드(10자리: 시도2+시군구3+읍면동3+리2) 또는 그 부분집합(시도/시군구/읍면동)이 아래 데이터셋에 **명시적으로** 존재한다.

| 데이터셋 | 지역 단위 | 코드 체계 |
|---|---|---|
| LX 국토정보필지 (5-1) | 필지(PNU, 법정동코드 포함) | 법정동코드 |
| 신한카드 SHC001/002 (6e) | 읍면동 | 법정동코드(2+3+3+2) `[CONFIRMED]` 정의서에 자릿수까지 명시 |
| LH 계약/관리비 (6g) | 시군구, 법정동코드(LGDN_CD) | 법정동코드(TB_COM_LGDN_C 참조) |
| KECO 클러스터 A/C/D (6h) | 시군구, 시도법정동코드/시군구법정동코드 | 법정동코드(10자리) |
| 국민연금 4종 (4) | 법정동/행정동 | cust_ldong_cd 등 |
| 한국도로교통공단 KRD_001 (6f) | 시도/시군구/읍면동 | 법정동 기준 명칭(코드 컬럼 없음, 명칭 매칭 필요) |
| 한국도로공사 KOTI 차량통행지표 (7-4) | 시도/시군구/읍면동 코드+명 | 자체 코드(법정동코드 일치 여부 VERIFY) |
| 대구상수도 7종 (2-2) | 읍면동/리 | 대구 한정, 명칭 기반(리 단위까지, 타 데이터보다 세밀) |
| BC카드 (6a) | 시군구 | 행정동 기준 코드 2/5자리 `[CONFIRMED]` |
| KCB 소득통계 (6b) | 행정동 | EMD_CD |
| 나이스지니데이타 (6d) | 시군구/상권명 | 서울 5개구·10개 상권 한정, 코드 없이 명칭 |
| KEPCO EV충전 (8) | 시군구/읍면동 | 명칭만(코드 컬럼 없음) |

```text
법정동코드(10자리)
    │
    ├── LX 국토정보필지 (PNU→법정동코드)  ── 필지 단위 최상세 지리 기준
    ├── 신한카드 SHC001/SHC002
    ├── LH 계약/관리비 (LGDN_CD)
    ├── KECO 클러스터 A/C/D (시군구법정동코드)
    └── 국민연금 4종 (ldong_cd)
```
- **연결 후보 key**: 법정동코드 10자리, 또는 앞 5자리(시군구)로 집계 수준 맞춤
- **시간 단위**: 데이터셋마다 상이(월/분기/일) — 조인 시 최소공배수 단위(월)로 재집계 필요 `[INFERRED]`
- **공간 단위**: 필지(LX) > 법정동/읍면동(신한카드, LH, KECO, 국민연금) > 시군구(BC카드, 대부분) > 시도(전국 요약) 순으로 세분화 정도 상이
- **정의서 명시 여부**: 각 데이터셋 내부의 관련 테이블 간 연결(예: 신한카드 SHC001-SHC002)은 `[CONFIRMED]`. **기관 간** 연결(예: LX 필지 ↔ 신한카드)은 정의서에 명시되어 있지 않으며 `[INFERRED]`(동일 코드체계를 표방하므로 이론상 가능) 수준이다.
- **VERIFY_WITH_DATA**: (1) 실제 코드 값의 자릿수/버전이 기관마다 동일한지(법정동코드 개편 시점 차이), (2) 도로교통공단·KEPCO처럼 코드 없이 "명칭"만 제공하는 데이터셋은 명칭 표기 불일치(예: "서울특별시" vs "서울") 정규화 필요, (3) 대구상수도처럼 "리" 단위까지 내려가는 경우 상위 데이터와의 집계 수준 정합

### 축 2 — 시간 (월 단위가 사실상의 공통 분모)
```text
월(YYYYMM)
    │
    ├── BC카드 (2025 전체)
    ├── SKT 유동인구 (2024 전체)
    ├── 신한카드 (2025 전체)
    ├── LH 계약/관리비 (2023~2026, 장기)
    ├── KEPCO EV충전 (2023~2025)
    ├── KECO 각 실적 (2022~2025)
    ├── 국민연금 (2026-04~06, 3개월만)
    └── 나이스지니데이타 (2022-11~2023-10 또는 2024-10)
```
- 2025년 기준으로 **동시에 겹치는 데이터셋**: BC카드(2025 전체), 신한카드(2025 전체), LH(계속), KEPCO(~2025-12), KECO 다수(~2025 or 2026 진행중) — 이 조합이 "2025년 지역 소비/에너지/주거/환경" 횡단 분석에 가장 안정적인 시간 교집합 `[INFERRED]`
- 국민연금 데이터는 **2026년 4~6월 3개월 스냅샷**뿐이라 시계열 분석에는 부적합하고, 동일 시점 횡단면 분석(예: 특정 분기의 지역별 소득/가입 구조)에 적합 `[INFERRED]`
- SKT 유동인구(2024), 나이스지니데이타(2022-2023/2024)는 다른 데이터셋과 연도가 어긋나 시계열 결합 시 갭 발생 `[VERIFY_WITH_DATA]`

### 축 3 — 산업/업종 분류 체계 (표준화 여부 주의)
세 가지 서로 다른 분류체계가 혼재한다:
1. **KSIC(한국표준산업분류, 통계청 표준)**: 국민연금(ksic_lctg/mctg_cd·nm), 나이스디앤비 기업재무(10차 표준산업분류)
2. **자체 상권분류체계**: 나이스지니데이타(대/중/소분류 자체 정의), 신한카드/BC카드(업종대/중분류 코드, "100대 생활업종" — 자체 체계)
3. **환경부/K-eco 폐기물 품목코드**: KECO 클러스터 B/C의 품목코드(코드표 별도 제공)

```text
KSIC(표준산업분류)
    │ (표준이므로 매핑 용이)
    ├── 국민연금 4종 (대/중분류 코드+명)
    └── 나이스디앤비 산업생태계 (대분류명)

자체 상권분류 (기관별 상이 — KSIC 매핑표 없이는 직접 비교 곤란)
    ├── 신한카드 업종대/중분류
    ├── BC카드 100대 생활업종
    └── 나이스지니데이타 대/중/소/세분류
```
- **VERIFY_WITH_DATA**: 신한카드·BC카드·나이스지니데이타의 자체 업종코드를 KSIC으로 매핑하는 공식 대응표가 제공되는지(코드파일 확인 필요). 없다면 명칭 기반 수작업 매핑이 필요하며 오차 발생 가능

### 축 4 — 좌표계 (공간 조인 시 반드시 재투영 필요)
| 데이터셋 | 좌표계 |
|---|---|
| LX 국토정보필지 (5-1) | GRS80 |
| SKT 유동인구 (6c) | UTM-K (50m 격자 X/Y) |
| ㈜이모션 교통량/카메라 (2-3) | WGS84 |
| KOTI 개별차량이동경로 (7-3) | WGS84 타원 |
| KECO 토양오염 (6h 클러스터G) | TM(중부원점) + 경위도 + UTM 3중 표기 |
- 좌표계가 다른 데이터셋을 공간 결합하려면 반드시 표준 좌표계(예: EPSG:5179 또는 WGS84)로 통일 후 처리해야 한다 `[INFERRED]`

## 3. 기관 간 잠재적 연결 (INFERRED, 실데이터로 검증 필요)

```text
[지역×시간 결합 후보 — "2025년 전국 시군구" 단면]
  BC카드 소비(6a)
      │ 시군구 + 월
      ▼
  신한카드 매출(6e) ── 시군구/읍면동 + 월 ──▶ KECO 폐기물시설(6h) ── 시군구 + 월
      │
      └──▶ LH 임대주택(6g) ── 시군구 + 월 ──▶ KEPCO EV충전(8) ── 시군구 + 월
```
- **가정**: 시군구(또는 읍면동) 코드를 공통 축으로 지역 소비력(BC/신한카드) × 주거(LH) × 에너지(KEPCO) × 환경(KECO)을 같은 시군구·같은 월 단위로 병렬 배치하는 것은 이론상 가능 `[INFERRED]`
- **VERIFY_WITH_DATA**: (1) 시군구별 실제 관측 커버리지가 데이터셋마다 다를 수 있음(신한카드는 8개 광역시도 한정, BC카드는 전국) — 교집합 지역만 유효, (2) 각 데이터셋의 결측 지역(소규모 시군구 등) 확인 필요

```text
[대구 지역 특화 결합 — 경북대 첨단기술원 내부 5개 하위 데이터 간]
  대구로 플랫폼(주문·배달·결제)  ── 읍면동/법정동 ──┐
  대구 상수도(고지정보 등)       ── 읍면동/리     ──┼──▶ 대구 시군구·읍면동 단위 공통 지역 프레임
  대구 교통량(이모션)           ── 좌표(WGS84)    ──┘
```
- **가정**: 대구광역시 한정이라는 공통점 때문에 대구로(소비)·상수도(생활)·교통량(이동) 데이터를 지역(읍면동) 단위로 병치해 "생활 인프라 종합" 관점의 지역 프로파일을 만들 수 있다 `[INFERRED]`
- **VERIFY_WITH_DATA**: 대구로/상수도는 코드 기반, 교통량은 좌표 기반이라 좌표→행정동 역지오코딩이 선행되어야 함

```text
[국민연금 이동량(4) ↔ 신한카드/BC카드 소비지역(6a,6e)]
  국민연금 자격_지역이동량 (거주 읍면동 ↔ 직장 읍면동)
      │ 읍면동 코드
      ▼
  신한카드/BC카드 지역 소비 (가맹점 소재 읍면동/시군구)
```
- **가정**: 국민연금의 거주-직장 OD 데이터와 카드사의 지역별 소비 데이터를 결합하면 "통근 인구 vs 소비 발생 지역"의 괴리(예: 직장 지역에서의 소비 vs 거주 지역에서의 소비) 분석 가능 `[INFERRED]`
- **제약**: 국민연금 데이터는 2026년 3개월 스냅샷뿐이라 시계열 비교는 불가, 특정 시점 단면 분석에 한정 `[VERIFY_WITH_DATA]`

```text
[LX 국토정보필지(5-1) ↔ 거의 모든 지역 기반 데이터]
  LX 필지(PNU, 법정동코드, 공시지가, 건물정보)
      │ 법정동코드 / 필지 좌표
      ▼
  (지역 단위로 집계되는 모든 데이터셋의 공간 기준 레이어로 사용 가능)
```
- **가정**: LX 필지 데이터는 공시지가·건물정보·도로명주소를 포함하므로, 다른 지역 집계 데이터에 "필지/건물 밀도, 지가 수준" 같은 파생 변수를 부여하는 **기반 지리 레이어**로 활용 가능하다고 정의서 스스로 언급(신용카드사 유동인구 결합 사례 명시) `[CONFIRMED]`(활용 의도) / `[VERIFY_WITH_DATA]`(실제 조인 성공률, 8.2GB 규모의 처리 가능성)

## 4. 연결이 어려운/불확실한 경우 (주의 표시)

- **가명화 ID는 기관 간 호환되지 않는다.** 건양대 RN_INDI, 경북대 CUST_ID/virtl_no, 경상북도개발공사 BZA_CD/CTCTR_NO, 국민연금 wkpl_nps_no는 모두 **발급 기관 내부에서만 유효한 가명키**로, 서로 다른 기관의 ID를 직접 매칭할 근거가 정의서에 없다. `[CONFIRMED]`(정의서에 교차 매칭 언급 없음)
- **케이플러스 온라인쇼핑(9-2), 나이스디앤비 기업재무(9-3)는 지역 코드가 없다.** 전국 단위로만 제공되어 다른 지역 기반 데이터와 직접 조인 불가 — 산업분류(나이스디앤비) 또는 상품분류(케이플러스) 축으로만 간접 연결 가능 `[CONFIRMED]`
- **LX 수치지형도의 "별표" 시트는 데이터가 아니라 법정 스펙 문서**이므로 다른 데이터셋과 조인 대상이 아니다.
- **좌표 기반 데이터(SKT, 이모션, KOTI)를 행정구역 기반 데이터와 결합하려면 공간조인(좌표→행정동 역지오코딩)이 선행되어야** 하며, 정의서만으로는 이 변환의 정확도를 알 수 없다 `[VERIFY_WITH_DATA]`
