# 방학 급식 사각지대 점검표 — 설계 (해결책 4번)

> **작성**: 2026-10-16 / **지위**: 해결책(실행전략) 층. 이 기획서의 분석을 대구시와 대구로 운영사가 **방학마다 다시 돌리는 도구**로 묶은 것이다.
> **0회차** = 이 기획서의 분석(2023-06~2025-06, 4차 반출, `analysis/outside/out_V4FBK/`). 그림 [T2_점검표_0회차_지도_시안.png](../report/T2_점검표_0회차_지도_시안.png)(`analysis/outside/97_checkup_map.py`).

## 1. 한 줄

방학이 끝날 때마다 운영사가 이미 가진 로그로 **"덜 쓰는 동 → 이유 7가지 → 담당별 처방"**을 한 번에 뽑아 대구시·구청에 넘기는 표.

## 2. 왜 필요한가 — 0회차가 보여 준 것

| 근거 | 수치 | 지위 |
|---|---|---|
| 가게를 늘려도 커버가 늘지 않는다 | 급식 주문을 받는 가게가 이미 아이의 99.9%를 덮는다(KCB 필요 무게). 가게 모집·활성화의 추가 효과 0, 가장 후한 설정에서도 방학 월 35계정 | 가정 층 |
| 겉보기 사각지대의 다수는 사각지대가 아니다 | 1순위 17곳 중 10곳이 제외(옆 동네 가게 이용 5, 지원 필요 가구 적음 5). **1순위의 겉보기 부족분(월 1,337건)의 65%가 이 10곳에 있다** | 판정 규칙 + 계산 |
| 진짜 부족분은 작고 흩어져 있다 | 처방 확정 4곳(배달형) 이용을 기대 수준의 50~100%까지 회복하면 방학 월 +6~12계정(이 4곳 기준 +57~114%). 미확정 3곳은 0~44 | 가정 층 |
| 덜 쓰는 곳은 일시적이지 않다 | 1순위 17곳 중 13곳, 처방 확정 4곳은 전부 방학 앞·뒤 반기 모두 하위 25%. 반기 간 순위 상관 0.785(156동) | 계산 |
| 기존 지원이 어디에 닿는지 볼 도구가 없다 | 배달비 지원 누적 약 6천 명·2억 7천만 원(2024-02 보도). 공개 자료로는 동별 도달을 알 수 없다 | 보도 + `[INFERRED]` |

→ **큰 사업 하나보다, 싸게 자주 점검해 몇 곳에 정확히 처방하는 장치가 맞다.**

## 3. 지금 넣을 수 있는 이유: 운영사 재공모

- 현 운영사(인성데이타) 협약이 **2026년 12월 말 종료**된다. 새 운영사 공모는 10/12~11/10이고, **2027-01-01부터 3년** 운영한다. 11월 말에 협약을 맺는다(아이뉴스24, 2026-10-11).
- 공모 조건에 **아동급식카드 결제 연계 필수**와 **가맹점 모집·관리 필수**가 있다. 데이터 제출 조건은 보도에 없다.
- 제안: **협약에 점검표 제출 의무를 한 줄로 넣는다.**
  > 예시 문구: "운영자는 매 방학 종료 후 30일 이내에 '방학 급식 사각지대 점검표'(법정동별 이용 지표, 이유 판정, 처방 대상)를 작성하여 시에 제출한다. 점검표는 동 단위 집계로 작성하며, 5건 미만 칸은 공개본에서 가린다."
- 운영사가 바뀌면 과거 로그가 끊길 수 있다. 그래서 **협약 종료 시 동 단위 집계를 인계**하는 조항을 함께 제안한다. 0회차(이 분석) 집계가 첫 기준선이 된다.

## 5. 입력 — 0회차와 운영 회차

운영 회차는 시·운영사가 가진 자료로 0회차의 "판단 불가" 칸을 채운다.

| 자료 | 가진 곳 | 0회차(이 분석) | 운영 회차 |
|---|---|---|---|
| 결제 로그(급식카드 표시, 완료, 가맹점, 시각, 금액, 계정) | 운영사 | 대구로 결제(상호제공) | 그대로 |
| 가맹점(주소, 급식카드 등록, 영업 상태) | 운영사 | 대구로 가맹점 | 그대로 |
| 배달(배차·완료·취소 시각, 배달팁) | 운영사 | 대구로 배달. 취소 표시는 4차 반출 결함으로 못 씀 | 그대로 |
| **필요(R1)** | 시·구청 | KCB 30·40대 저소득 비율(대리) | **법정동별 급식카드 대상 아동 수**로 교체(직접) `[INFERRED: 대상 아동은 읍면동 신청으로 관리]` |
| **1끼 가능 가게(R4)** | 운영사 DB | 팀원 앱 점검 27곳(2026-10 화면) | **주소별 배달 가능 급식 가게의 급식카드 기준 최소주문·최저 메뉴로 자동 계산**. 전 동 가능 |
| **신청 끼니·안내(R6)** | 구청 | 동 판정 없음 | 법정동별 신청 유형(학기/방학 × 끼니) 비중 → 동 판정 가능 |
| 다른 경로(R2) | 공개 | 못 씀 | 지역아동센터 정원 등 |
| 집 동 → 가게 동 흐름(R7) | 운영사 | 4차 반출 결함으로 11% 표본만 → 이웃 비교(약)로 대체 | 배달 주소 기준으로 직접 계산 |
| 아동 인구, 대응표, 경계 | 공개 | 그대로 | 그대로 |
| 매장 결제(앱 밖 급식카드 이용) | 시(카드 운영) | 없음 | **확장**: 같은 방식으로 결합하면 앱 밖 이용까지 본다 |

## 6. 처리 순서 (매 회차 같다)

**0. 자료 점검 (자동)** — 4차 반출에서 실제로 난 오류를 그대로 점검 항목으로 만들었다.

| 점검 | 잡는 오류 | 4차에서 실제로 |
|---|---|---|
| 급식 결제 합 = 원장 합 | 반복문 들여쓰기 등으로 일부만 집계 | M2가 341,216건 중 38,854건만 담았다 |
| 기간 최소·최대 출력 | 날짜 조건 오타 | Q7이 매달 1~20일만, 상한 없이 집계 |
| 취소율이 0%도 100%도 아님 | 취소 표시 조건 오류 | 취소율 1.0 |
| 코드 연결: 연결 안 된 인구 비율 | 출장소·신설 동 | KCB 출장소 2곳으로 논공·다사 R1 판단 불가 |
| 공개본: 5 미만 칸 없음, 출력에 억제 전 표 없음 | 억제 누락 | 3차 레짐 파일, 4차 노트북 출력 |

**1. 덜 쓰는 동 찾기** — 방학 LQ(같은 동 일반 배달 대비 급식 비중) 하위 25% + 등록 가게 3곳 이상 + 아동 1천 명당 이용이 중앙값 미만 → 1순위(D-015~017 규칙 그대로). 직전 회차에도 1순위였는지(지속성)를 같이 적는다.
- **문턱 두 가지**: 그 회차 분포의 25%(새로 나빠진 곳 찾기)와 **0회차 문턱 고정**(개선 추적). 상대 문턱만 쓰면 어느 회차든 4분의 1은 늘 "덜 쓰는 곳"이 된다.

**2. 이유 7가지 판정** — D-019 규칙 그대로. 판정 기호는 해당 / 아님 / 판단 불가. 억제 칸은 두 끝으로 두 번 판정한다.

**3. 유형과 담당**

| 유형 | 조건 | 담당 | 처방 예 |
|---|---|---|---|
| 제외: 옆 동네 이용 | R7 | — | 처방하지 않음. 다음 회차 관찰 |
| 제외: 필요 적음 | R1 | — | 처방하지 않음 |
| 공급형(활성화/모집) | R3 | 운영사 | 쉬는 등록 가게 재활성화, 가맹점 모집(MCLP 목록 순서) |
| 가격형 | R4 | 대구시·구 + 운영사 | 급식카드 최소주문 면제 가게 확대, 1만 원 이하 1인 메뉴, **목록에 면제 표시** |
| 배달형 | R5 | 운영사 | 배달 가능 범위·배달 시간 개선(방학 정기 배달편 등). **배달비는 이미 지원 중이라 비용이 아니라 배달이 오는지가 문제** |
| 안내형(잔여 추정) | R6 | 구청 | 방학 전 안내(보호자와 아이 모두. 표본상 계정 명의자의 약 3분의 1이 10대), 신청 끼니 점검 |
| 미확정 | 판단 불가 남음 | 구청 | 현장 확인 질문지 → 다음 회차 반영 |

**4. 추적** — 처방한 동의 다음 회차 지표를 처방하지 않은 같은 규모 동의 자연 변동과 비교한다(방법은 [T2_pilot_design.md](T2_pilot_design.md) §4).

## 7. 산출물 (회차마다)

1. **지도 1장**: 1순위와 유형(0회차 시안 = 위 그림)
2. **판정표**: 공개본은 기호와 유형만, 내부본은 지표 값과 사유
3. **동별 카드(내부)**: 지표, 대조 동, 처방, 직전 회차 대비 변화
4. **요약 지표**

## 8. 비용과 부담

- **새 자료 수집이 없다.** 입력은 운영사 로그, 시·구청 보유 자료, 공개 자료다.
- 계산은 이 기획서의 코드 그대로다(`analysis/outside/90·80·85·97`, 센터 셀 M2·Q1·Q3·Q7 등). 집계 표에서 판정·시나리오·지도까지 노트북 PC로 약 1분이다(0회차 실측: 90 11초, 80 약 30초, 85 약 6초, 97 5초). 원 로그에서 동별 집계를 만드는 단계(센터 셀에 해당)는 결제 파일(641MB)을 여러 번 읽어 십수 분이 더 든다.
- 사람의 일은 자료 추출, 점검 기록 확인, 미확정 동 현장 확인이다. 회차당 1~2인일로 본다 `[INFERRED]`.

## 9. 확산

- **같은 구조의 다른 지역**: 급식카드를 받는 공공배달앱이면 입력이 같다(결제 로그 + 가맹점 + 아동 인구 + 필요 지표).
- **매장 결제 결합**: 시가 가진 급식카드 전체 결제를 같은 방식으로 넣으면 앱 밖 이용까지 본다. 이 분석의 가장 큰 한계(앱 결제만 봄)가 풀린다.
- **다른 바우처**: 지역·시간에 따라 이용이 갈리는 다른 바우처에도 "덜 쓰는 곳 → 이유 판정 → 처방" 틀을 적용할 수 있다 `[INFERRED]`.

## 10. 한계

- 0회차는 앱 결제만 봤다. 외곽의 낮은 이용 일부는 매장 결제일 수 있다(운영 회차에서 결합으로 해소).
- R1 필요는 성인 소득 대리였다(운영 회차에서 대상 아동 수로 교체).
- 작은 동은 건수가 적어 반기마다 크게 흔들린다(반기 50건 이하 동의 자연 변동 SD 0.59, 로그). 그래서 지속성과 0회차 문턱 고정을 같이 본다.
- 판정 문턱(하위 25%, 중앙값)은 상대 기준이다. 규칙은 회차마다 바꾸지 않고, 바꿀 때는 이유와 이전 결과를 함께 적는다(D-019 방식).
