**KCB 소득 데이터 병용 원칙**: `읍면동소득신용통계정보`는 **연소득 7구간**(최저 = 연 2천만원 = 월 167만원)이라 저소득 해상도가 거칠다. KCB004는 **월환산 22구간**(최저 = 월 100만원 이하)이라 **저소득 식별에 더 정밀**하다. T2의 필요도 `W(d)`는 최하단 구간이 핵심이므로 **KCB004를 주 지표로 유지**하고, 읍면동 버전은 지역 결합의 다리·중위소득·불평등 지표로 쓴다.

**새 제약**: 읍면동소득신용통계정보는 성별×연령 셀 단위인데 **인구수 컬럼이 없다.** 동 단위 대표값을 만들 때 가중치가 없어 단순평균하면 인구 적은 셀이 과대 반영된다 → KCB004의 셀별 인원수 또는 읍면동소비신용의 `카드보유자수`를 가중치로 사용한다 `[VERIFY_WITH_DATA — 축 일치 여부]`.

#### I. 신청 화면에서 확인된 운영 사실 `[CONFIRMED]`

- **데이터를 사전 지정해 신청한다** (센터선택 → 신청자료선택 → 이용신청서작성 → 이용기간선택 → 신청완료). 방문 후 현장에서 추가로 여는 방식이 아니다 → **fallback 데이터를 미리 신청해야 한다.** 미해결 E 항목 하나 해소.
- **`[기간]` 대괄호 접두어 = 대회용 상호제공 버전**(안심구역 지정기관 명의), 접두어 없음 = **센터 자체 보유분**(원 제공기관 명의) `[INFERRED — 표기 패턴]`. 같은 데이터가 두 명의로 중복 등록돼 있다.
  → 가점 +5는 "상호제공데이터 연계 활용"이므로, **기획서 데이터 목록 표에 분류 컬럼을 두어 둘을 구분**한다.
- **대구로 미리보기는 상호제공 버전에서는 제공되지 않는다**(인성데이타 명의 원본에서만 확인 가능).

## 2. 결제-주문-배달-가맹점 결합 규칙 설계

### 2.1 문제의 정확한 형태

리뷰(일 단위)를 제외한 4개 테이블 중 가맹점(`INS_004`)은 `SHOP_ID` 단일키로 **무손실 결합**된다. 문제는 **결제·주문·배달 3자 결합**이다.

```text
INS_006 주문   8,767,828   키: SHOP_ID, CUST_ID, ORDER_DT(시)
INS_001 결제   7,881,627   키: SHOP_ID, CUST_ID, CARD_APP_TIME(시)
INS_003 배달   7,319,571   키: SHOP_ID, CUST_ID, DELI_ALLOC_TIME(분)
```

공통 식별자는 (`SHOP_ID`, `CUST_ID`, 시각)뿐이고, **주문번호가 없다** `[CONFIRMED]`.

건수 차이가 시사하는 구조 `[INFERRED]`:
- 주문 − 결제 ≈ 886K → 결제 미발생(만나서결제·결제대기·주문 취소) 또는 결제 테이블의 별도 필터
- 주문 − 배달 ≈ 1,448K → 포장주문(`PACK_YN='Y'`) 및 취소

따라서 **결합 실패의 상당 부분은 "매칭 실패"가 아니라 "실제로 대응물이 없음"** 이다. 매칭률 평가 시 이 둘을 반드시 분리해야 한다(§2.3 M2).

**핵심 위험**: 동일 고객이 동일 가맹점에 **같은 시(hour)에 두 건 이상** 주문하면 결제와 주문의 대응이 모호해진다. 이 모호 비율이 매칭 규칙 선택의 전부를 결정한다.

### 2.2 매칭 규칙 후보 3종

#### R1 — 정확 키 1:1 (엄격, 기준선)

키 = (`SHOP_ID`, `CUST_ID`, `YYYYMMDDHH`). 셀 내 주문 1건·결제 1건인 경우에만 결합하고, 셀 내 다중이면 **전량 폐기**(모호 표시).

- **장점**: 오매칭 0. 결과의 내적 타당성 최상.
- **단점**: (a) 시 경계에서 주문 18:59 → 결제 19:00인 건이 전부 유실. (b) 다중 셀 폐기가 **활동량 많은 가맹점·고객에 편중**되므로 결합 표본이 저활동 쪽으로 치우친다(선택 편의).
- **용도**: 오매칭을 최소화한 **기준선**. 다른 규칙의 결과를 여기에 대조한다.

#### R2 — ±1시간 창 + 최근접 1:1 배정 (주력 후보)

셀을 (`SHOP_ID`, `CUST_ID`)로 잡고, 결제 시각과 주문 시각의 차가 **[−1h, +2h]** 인 후보쌍을 만든 뒤, |Δt| 최소를 목적함수로 하는 **1:1 배정**(가맹점-고객-일 블록 단위 그리디 또는 헝가리안)을 수행한다.

- **창의 비대칭성 근거**: 주문 후 결제·승인이 발생하므로 결제는 주문보다 **뒤에** 오는 것이 자연스럽고, 시 단위 절삭으로 −1h가 발생 가능하다 `[INFERRED]`. 실제 부호 분포는 게이트 점검에서 확인 `[VERIFY_WITH_DATA]`.
- **동점 처리**: |Δt| 동점이면 **결합 보류**(모호 표시). 임의 배정 금지.
- **구현**: DuckDB `ASOF JOIN` 또는 range join + `row_number()` 기반 그리디. 8.7M×7.9M 규모라 전량 cross join은 금물이며, 반드시 (SHOP_ID, CUST_ID) 파티션 내에서만 후보를 만든다.
- **배달 결합**: `DELI_ALLOC_TIME`을 시로 절삭한 뒤 주문에 대해 **[0, +2h]** 창의 ASOF(주문 이후 최초 배치)로 붙인다. 배차는 주문보다 뒤에 오므로 단측 창이 타당하다 `[INFERRED]`.

#### R3 — 결합 포기, 셀 단위 집계 (강건 대안)

개별 건을 잇지 않고, **(`SHOP_ID`, 날짜, 시)** 셀에서 세 테이블을 각각 집계한 뒤 셀을 단위로 분석한다.

- 셀 변수: 주문건수, 급식카드 결제건수, 급식카드 결제금액 합, 배달 건수, 취소 건수, 평균 배차→완료 소요분, 평균 배달팁.
- 이때 H3은 개인 단위 처치효과가 아니라 **"그 가맹점-시간 셀의 급식카드 비중이 높을수록 배달 소요·취소가 어떠한가"** 라는 **강도(intensity) 회귀**가 된다. 가맹점 고정효과는 그대로 사용 가능.
- **장점**: 매칭 오차가 원리적으로 존재하지 않는다. **단점**: 개별 주문 단위 매개분석이 불가능하고, 추정 대상이 생태학적 수준으로 바뀐다.
- **용도**: R2 매칭률이 낮거나 R1과 R2의 결과가 어긋날 때의 주력 대안이자, **어떤 경우에도 수행하는 강건성 검사**.

### 2.3 매칭률 측정 지표

각 규칙 g ∈ {R1, R2}에 대해 다음을 계산하고 표(T0)로 병렬 제시한다.

| 지표 | 정의 | 판정 |
|---|---|---|
| **M1 결합률(결제 기준)** | 결합된 결제 건수 / 전체 결제 건수 | 높을수록 좋음 |
| **M2 결합률(주문 기준)** | 결합된 주문 건수 / (전체 주문 − 결제 대응 불가 추정분) | 분모 정의를 반드시 명시 |
| **M3 모호율** | 다중 후보로 보류된 건 / 후보가 1개 이상인 건 | 낮을수록 좋음. **매칭 가능성의 본질** |
| **M4 논리 정합** | 결합쌍 중 `ORDER_ST`와 `CARD_PAY_GBN`의 정합 비율(완료↔완료, 취소↔취소) | 무작위 매칭이면 주변분포 곱에 수렴 |
| **M5 편중도** | 결합 성공 표본 vs 전체 표본의 가맹점 활동량·시간대·행정동 분포 차이(SMD) | \|SMD\| < 0.1 목표 |

**M6 — 순열 위약검정(가장 중요).**
(`SHOP_ID`, 날짜, 시) 블록 **안에서** `CUST_ID`를 무작위 셔플한 뒤 동일 규칙을 재실행한다. 여기서 나오는 매칭률이 **"키가 아무것도 식별하지 못할 때의 매칭률"**, 즉 식별력의 하한이다.

- 실제 매칭률 ≫ 위약 매칭률 → 키가 실제로 개별 거래를 식별한다.
- 실제 ≈ 위약 → **(SHOP_ID, CUST_ID, 시)는 사실상 식별력이 없으므로 R3(셀 집계)로 전환한다.**

이 검정을 기획서에 표로 싣는 것 자체가 "전처리·분석 방안의 타당성"(예선 논리성 30점)에 직접 기여한다.

**M7 — 사전 진단(결합 실행 전 1분이면 끝난다).**
`INS_006`에서 (`SHOP_ID`, `CUST_ID`, `ORDER_DT`) 조합의 **중복도 분포**를 먼저 본다. 조합의 "1건" 비율이 높을수록 R1/R2가 잘 작동한다. 이 한 장의 표가 규칙 선택의 근거가 된다 `[VERIFY_WITH_DATA]`.

### 2.4 규칙 선택 절차

```text
M7 사전 진단 (조합 유일성 분포)
      ↓
R1 실행 → M1~M5
R2 실행 → M1~M5,  R2 위약 실행 → M6
      ↓
 ├── R2 결합률 충분 & M6 통과 & M3 낮음 ──▶ R2 주력, R1을 강건성 검사
 ├── R2 결합률 충분 & M5 편중 큼 ─────────▶ R2 + 역확률 가중(결합 성공확률의 역수)으로 편중 보정
 └── M6 실패(실제≈위약) 또는 M3 과다 ─────▶ R3(셀 집계)로 전환, H3을 강도 회귀로 재정식화
```

**최종 결과는 세 규칙 모두에서 재현되는지 보고한다.** H3의 핵심 계수를 R1/R2/R3 세 열로 나란히 놓은 표(T4)를 기획서에 싣는다 — 심사에서 "결합의 완성도"를 보여주는 가장 효과적인 장표다.

### 2.5 결합하지 않아도 되는 부분 — 리스크 격리

| 가설 | 필요한 결합 | 결합 실패 시 |
|---|---|---|
| H1 (급식카드의 시공간 프로파일) | `INS_001` ⋈ `INS_004` (**SHOP_ID 단일키, 무손실**) | **영향 없음** |
| H1-b (행정동 분포) | 동일 | **영향 없음** |
| H2 (가맹점 공간 정합성) | `INS_004` + 외부 (행정동만) | **영향 없음** |
| H4 (가맹점 폐업) | `INS_004` + `INS_006` 집계 (SHOP_ID) | **영향 없음** |
| H5 (단가 집군) | `INS_001` 단독 (+ `INS_004`) | **영향 없음** |
| **H3 (배차 형평성·매개)** | **결제⋈주문⋈배달 3자 결합 필수** | R3로 재정식화, 또는 H3 축소 |

## 3. 변수 수준 분석 설계

### 3.1 행정동 × 시간대 "급식카드 사용 가능성 지수"

#### 3.1.1 영업시간을 무엇으로 대리하는가

`INS_004`에 영업시간 컬럼이 없다 `[CONFIRMED]`. 유일한 대리변수는 **그 가맹점에서 실제로 주문이 발생한 시간대 분포**(`INS_006.ORDER_DT`)다.

가맹점 s, 요일-시간(hour-of-week) h, 월 m에 대해:

```text
π(s, h, m) = (월 m 중 시간 h에 s의 주문이 1건 이상 발생한 날의 수)
             ────────────────────────────────────────────────────
             (월 m 중 해당 요일의 총 일수)
```

`π ∈ [0,1]` — "그 가맹점이 그 요일·그 시간에 열려 있을(주문을 받을) 확률"의 대리값.

**이 대리값의 결정적 약점과 대응** `[INFERRED]`

- **문제**: **"닫혀 있음"과 "열려 있지만 주문이 없음"이 구분되지 않는다.** 주문량이 적은 가맹점은 실제보다 닫힌 것처럼 보인다.
- **대응 ① 표본 제한**: 월 주문건수가 임계치 미만인 가맹점은 지수 산정에서 제외하고 제외분 규모를 보고한다. 임계치는 8/12/20건 세 가지로 민감도 분석.
- **대응 ② 정규화**: 가맹점의 총 주문량에 영향받지 않는 **상대 프로파일** `π̃(s,h) = π(s,h) / max_h π(s,h)` 를 함께 계산한다.
- **대응 ③ 외부 검증**: 신한카드 SHC002의 `TIZO_CLCD`가 주는 **행정동×시간대 외식 결제 분포**와 π 집계값의 상관을 확인한다. 두 독립 출처가 같은 시간 구조를 보이면 대리값의 타당성이 크게 보강된다. **기관 간 연계가 방법론적 정당화에 쓰이는 지점** — 연계 점수와 논리성 점수를 동시에 얻는다.
- **대응 ④ 정직한 명명**: 지수를 "영업시간"이 아니라 **"관측된 주문 수용 가능성(observed order-serving availability)"** 으로 부른다.

#### 3.1.2 공급 측 — 유효 급식 가맹점 수

행정동 d, 시간 h, 월 m:

```text
S(d, h, m) = Σ π(s, h, m)     … s ∈ {CHILD_ABLE_YN='Y', 행정동 d, 월 m에 영업}
```

"월 m에 영업"의 판정: `STORE_STATUS` ≠ 03 이거나 `CLOSED_AT` > m, 그리고 그 달에 주문이 1건 이상 관측 `[INFERRED]`.

**공간 시차 보정 (§0-B 대응)** — 배달은 동 경계를 넘으므로 자기 동만 세면 과소평가된다.

```text
S*(d, h, m) = S(d, h, m) + λ · Σ S(d', h, m)     … d' ∈ N(d) (인접 행정동)
```

- `N(d)`는 통계청 SGIS 행정동 경계 shp에서 계산한 인접 집합(rook 인접).
- λ는 이웃 동의 기여 가중치. **λ ∈ {0, 0.25, 0.5}** 세 값으로 전 결과를 재현한다. λ=0이 §0-B 이전의 원 설계이므로, **세 값 비교 자체가 "동 경계를 넘는 배달"의 영향을 정량화하는 결과**가 된다.
- 실제 배달 거리 분포는 관측 불가하므로 λ를 데이터에서 추정할 수 없다 `[CONFIRMED — 목적지 컬럼 부재]`. **민감도 분석으로만 다루며, 추정된 값처럼 제시하지 않는다.**

#### 3.1.3 수요 측 — 필요도

```text
N(d) = 행정동 d의 아동 인구(6~18세)   ← 행안부 주민등록 연령별 인구  [공개]
W(d) = 행정동 d의 저소득 성인 비율 = (C1+C2+C3)_d / Σ_k (Ck)_d   ← KCB004 [2022Q1~2023Q4]
```

KCB에 아동이 없으므로(§1.9) `W(d)`는 **필요도의 보조 대리변수**이며, 주 분모는 공개 아동 인구다. 지자체의 **아동급식 지원대상 아동 수**가 동 단위로 공개된다면 이를 우선 사용한다 `[VERIFY]`.

#### 3.1.4 지수 정의

```text
DCAI(d, h, m) = S*(d, h, m) / (N(d) / 1000)
```

**대구 아동급식 접근성 지수(Daegu Child-meal-card Accessibility Index)** = 아동 1,000명당, 그 시간에 실제로 주문을 받는 급식 가능 가맹점 수.

보조 지표 3종:

- **상대 커버리지** `ρ(d,h,m) = S*_급식(d,h,m) / S*_전체(d,h,m)` — 그 동·그 시간에 열린 가맹점 중 급식카드를 받는 비율. **인프라 자체가 얇은 동**과 **가맹점은 있는데 급식은 안 받는 동**을 분리한다.
- **시간 균등성** `E(d,m) = 1 − Gini_h(S*(d,h,m))` — 하루 중 특정 시간에만 몰리는지.
- **수요 대비 커버리지** `ρ_demand(d,h) = S*_급식(d,h) / (신한카드 d,h 외식 결제건수)` — 실제 소비 수요가 있는 시간대에 급식 수용 공급이 따라오는가. **기관 간 연계가 지표에 직접 들어가는 지점.**

**사각지대 판정 규칙** (사후 임의 기준이 아니라 **사전 등록**):

> 행정동-시간 셀 (d,h)가 **동시에** ① `DCAI(d,h)`가 대구 전체 분포의 하위 25% ② `N(d)`가 중위 이상 ③ 해당 시간대 신한카드 외식 결제건수가 중위 이상(수요는 있음) 이면 **사각지대**로 분류.

임계값은 25%/중위로 고정하고, 10%·33% 대안으로 민감도 분석한다.

#### 3.3.1 결과변수 재정의 (§0-C)

#### 3.3.2 모형

처치 `D = 1{결합된 주문의 PAY_GBN = '아동급식카드'}`.
매개변수 `M1 = DELI_TIP_AMT`(배달팁), `M2 = log(TOT_AMT)`(주문금액).

```text
(1) 총효과      Y   = τ ·D                    + α_s + γ_hw + δ_m + X'β + ε
(2) 매개 경로   M_k = a_k·D                   + α_s + γ_hw + δ_m + X'β + u    (k=1,2)
(3) 직접효과    Y   = τ'·D + Σ_k b_k·M_k      + α_s + γ_hw + δ_m + X'β + e
```

- `α_s` **가맹점 고정효과 — 필수**([TOPIC_EVALUATION.md](../TOPIC_EVALUATION.md) §1 C01 Methodology). 급식 가맹점의 업종·입지가 애초에 다르다는 문제를 **가맹점 내 비교**로 제거한다. **업종 컬럼이 없으므로(§0-A) 이것이 유일한 방어다.**
- `γ_hw` 요일-시간 FE(168), `δ_m` 연월 FE(최대 42).
- `X` = `COOK_WAIT`·`ORDER_WAIT`(순서형 더미), `PACK_YN`, `GOOD_ORD_YN`, 동시간대 동별 주문밀도(파생 혼잡도), 고객 `BR_DT`·`GENDER`(§7.1 제약 하에 통제변수로만).
- 표준오차: **가맹점 클러스터**. 2-way(가맹점 × 연월)도 병기.

**추정 대상**: 총효과 `τ`, 직접효과 `τ'`, 매개효과 `Σ a_k·b_k`(product of coefficients), 매개 비율 `1 − τ'/τ`.
**신뢰구간**: **가맹점 단위 블록 부트스트랩 1,000회**(클러스터 구조 보존).
결과가 이진일 때는 KHB 방법 또는 선형확률모형을 병기한다 — 로짓 계수의 스케일 문제로 τ와 τ'의 직접 비교가 왜곡되므로, 이 점을 각주로 명시한다.

**정직성 요건 (기획서에 반드시 명시)**

1. 매개분석의 인과 해석은 **순차적 무시가능성**을 요구한다. 배달팁은 소비자의 선택이고 미관측 요인(급한 상황, 날씨 체감)이 팁과 소요시간에 동시에 영향을 줄 수 있다. → **본 분석의 매개분해는 인과적 매개효과가 아니라 "관측 가능한 가격 경로를 통한 기술적 분해"** 로 표현한다.
2. **민감도 분석**: 매개변수-결과 미관측 교란의 상관 ρ에 대해 매개효과가 0이 되는 ρ를 보고(Imai·Keele·Yamamoto 방식).
3. **어느 방향이 나와도 결론이 있다** — `τ'≈0`이면 "가격 메커니즘이 격차를 만든다"(정책: 급식 주문 배달팁 보조), `τ'≠0`이면 "가격으로 설명되지 않는 잔여 격차가 있다"(정책: 우선 배차 규칙). [TOPIC_EVALUATION.md](../TOPIC_EVALUATION.md) §1의 방어 논리를 그대로 실행한다.

#### 3.3.3 선택 편의 대응 — 성향점수 매칭

가맹점 FE가 있으면 **가맹점 내에서 급식·일반 주문이 모두 관측되는 가맹점**만이 식별에 기여한다. 이 집합이 얇으면 FE 추정이 불안정하므로, 병렬로 **가맹점 수준 PSM 표본**을 만들어 대조한다.

**매칭 단위**: 가맹점(`SHOP_ID`). **처치**: `CHILD_ABLE_YN='Y'`.
**정확 일치(exact match)**: `GUNGU_NM`(대구 구·군), 플랫폼 최초 관측 반기.
**성향점수 로짓의 공변량** — 업종이 없다는 제약 하에서 업종·규모·입지를 대리하도록 설계:

| 범주 | 변수 | 출처 |
|---|---|---|
| 규모 | log(월평균 주문건수), 월평균 결제금액 중위값, 고유 고객 수 | INS_006, INS_001 |
| 가격대 | 주문금액 분위(p25/p50/p75), 배달팁 중위값 | INS_001, INS_003 |
| **업종 대리** | **시간대 주문 프로파일 벡터의 주성분 1~3** (24차원 정규화 프로파일 → PCA) | INS_006 |

**매칭 절차**: 1:2 최근접, 캘리퍼 = 로짓 성향점수 SD의 0.2, 복원 없음, 공통 지지 밖 제외.
**균형 진단**: 전 공변량 |SMD| < 0.1, 분산비 0.5~2.0, 성향점수 밀도 중첩 그림. **균형표(T5)를 기획서에 그대로 싣는다.**
**민감도**: Rosenbaum bounds로 미관측 교란에 대한 Γ 임계값 보고.

### 3.4 H4 — 가맹점 생존분석의 구조적 한계와 처리

`INS_004`는 **스냅샷**이다 `[CONFIRMED]`. 다음 세 가지가 관측되지 않는다.

1. **가맹 시작 시점** — 컬럼 없음 → **최초 관측 주문월**로 대체(좌측 절단. 2022-01에 이미 활동 중인 가맹점은 절단 표시).
2. **`CHILD_ABLE_YN`이 언제 Y가 되었는지** — 스냅샷 값 → 전 기간 불변으로 **가정**하고, 이 가정이 틀릴 경우의 방향(급식 등록이 폐업 직전 늘어난다면 위험 과대추정 등)을 명시.
3. **`STORE_STATUS`가 언제 바뀌었는지** — `CLOSED_AT`(YYYYMM)만 폐업에 대해 존재. 휴업(02) 시점은 알 수 없다.

따라서 H4는 **폐업(03, `CLOSED_AT` 있음)만을 사건으로 하는 이산시간 해저드**로 한정한다.

- 위험집합: 월 단위. 진입 = 최초 관측 주문월, 종료 = `CLOSED_AT` 또는 2025-06 우측중도절단.
- 모형: `logit P(폐업_{s,m} | 생존) = f(경과월) + θ·CHILD_ABLE_s + 시간변동 공변량 + 연월 FE`
  시간변동 공변량: 직전 3개월 주문건수 추세, 취소율, 평균 별점 추세, 재구매 고객 비율.
- **PSM 표본에서 재추정**(§3.3.3과 동일 매칭)하고 Kaplan-Meier를 병기.

### 4.2 건수 임계값별 분기 기준

임계값은 **"어떤 분석에 최소 몇 건이 필요한가"로부터 역산**했다. 예측이 아니라 **사전 등록된 의사결정 규칙**이다.

#### 역산 근거

| 분석 | 셀·모수 구조 | 필요 표본 |
|---|---|---|
| H1 요일-시간 프로파일 | 24시간 × 7요일 = **168셀**. 셀당 안정적 비율 추정에 최소 30건 | **≈ 5,000** |
| H1-b 행정동 × 시간구간 | 상위 30개 동 × 6개 시간구간 = 180셀 × 30건 | **≈ 5,400** |
| **핵심 산출물(동×요일시간 히트맵)** | 상위 30개 동 × 168셀 = 5,040셀 × 20건 | **≈ 100,000** |
| H3 로지스틱(가맹점 FE) | 저빈도 사건. 공변량 20개에 EPV ≥ 10 → 사건 200건 필요 → 표본 200/p. p=2%면 10,000. **결합 손실 30% 가정** 시 원 결제 기준 | **≈ 15,000~30,000** |
| H3 가맹점 FE 식별 | 급식·일반이 **모두 있는 가맹점** 300개 이상, 가맹점당 급식 주문 ≥ 10건 | **가맹점 300개 이상** |
| H3 매개분석 부트스트랩 | 간접효과 추정 안정성 위해 **결합 후** 유효 표본 ≥ 10,000 | **≈ 10,000(결합 후)** |
| H5 집군 분석 | 100원 폭 빈, 관심 구간 ±3,000원에 60빈, 빈당 ≥ 30건 | **≈ 2,000** |
| H2·H4 | 급식카드 결제 건수와 **무관**(가맹점 22,087개 전수 사용) | **0** |

#### 분기 규칙 (사전 등록)

> `N` = `PAY_GBN='아동급식카드'` 총 결제 건수 / `N_SHOP` = 급식카드 결제가 발생한 고유 가맹점 수 / `MONTHS` = 급식카드 결제가 1건 이상인 월 수.

| 분기 | 조건 | 수행 범위 |
|---|---|---|
| **원안 (Full)** | `N ≥ 100,000` **AND** `N_SHOP ≥ 500` **AND** `MONTHS ≥ 24` | H1, H1-b, H2, H3(가맹점 FE + 매개분석 + PSM), H4, H5 **전부**. 핵심 산출물인 행정동×요일시간 히트맵을 개별 결제 기반으로 작성 |
| **원안 축소 (Reduced)** | `20,000 ≤ N < 100,000` **OR** (`N ≥ 100,000` 이나 `N_SHOP < 500`) | H1·H1-b는 시간축 6구간·행정동 상위 30개로 축소. **H2·H4·H5는 전부 유지.** H3은 **가맹점 FE 포기**, PSM 매칭 가맹점 표본 + 행정동 FE로 추정하고 **매개분해는 층화 기술통계 수준으로 강등**. 사각지대 히트맵은 §3.1의 **가맹점 기반 DCAI**(결제 건수 불필요)로 작성 |
| **1차 fallback** | `2,000 ≤ N < 20,000` **OR** `MONTHS < 12` | **분석 단위를 결제에서 `가맹점 × 월`로 격상.** 주력은 `CHILD_ABLE_YN` 22,087개 전수 기반 **접근성·커버리지·폐업 생존 분석**(H2·H4 + DCAI). 급식카드 결제는 "그 가맹점이 그 달에 급식 수요를 실제로 받았는가"의 이진·카운트 지표로만 사용해 **DCAI의 외부 타당성 검증**에 투입. **H5는 유지**(집군은 이 구간에서도 성립). H3 폐기 |
| **2차 fallback** | `N < 2,000` **OR** `N_SHOP < 50` **OR** `PAY_GBN`에 '아동급식카드' 값이 실재하지 않음 | **주제를 C03(배차 실패의 시공간 구조 — "배달 사막")으로 전환.** 취약계층 축은 `GOOD_ABLE_YN`(착할매장)·`PAY_GBN='온누리상품권'`으로 대체. **결합 규칙(§2)·DCAI 골격(§3.1)·시각화 스펙(§6.4)·행정동 브리지(§5.1)는 전부 재사용** — 전환 비용은 문제 정의와 서술뿐 |

**임계값의 근거 요약**

- **100,000** = 핵심 산출물(행정동 30 × 요일-시간 168 히트맵)이 셀당 20건을 확보하는 최소치. 동시에 결합 손실 후에도 H3 매개분석 유효표본 10,000을 남긴다.
- **20,000** = 시간축을 6구간으로 병합하고 공간을 상위 30개 동으로 줄인 축소판이 성립하는 최소치. 사건율 2% 가정에서 H3 로지스틱의 EPV 요건도 결합 손실 후 충족.
- **2,000** = H5 집군 분석의 하한. 이 아래로는 개별 결제 수준의 어떤 추론도 방어할 수 없다.
- **`N_SHOP ≥ 500` / `≥ 50`** — 건수만으로는 부족하다. 결제가 소수 가맹점에 몰려 있으면 공간 분석이 성립하지 않고 §7.2의 최소 집계 기준(R-2)에도 걸린다. **건수와 가맹점 수를 동시에 요구하는 이 조건이 실질적 게이트일 가능성이 있다** `[VERIFY_WITH_DATA]`.
- **`MONTHS ≥ 24`** — 구조 변화 탐지(§4.3)와 시간 FE 추정에 필요한 최소 시계열 길이.

**분기 결정은 1일차 종료 전에 문서로 확정하고 번복하지 않는다.** 결과를 보고 기준을 바꾸는 사후 임계값 조정은 금지한다.

### 4.3 월별 추이로 구조 변화 탐지

배달앱 아동급식카드 결제는 특정 시점에 **도입**됐을 가능성이 높다 `[INFERRED — 검증 필요]`. 42개월 중 어디부터가 "정상 운영 구간"인지 정해야 분석 기간이 확정된다.

**3층 시계열 구성**

```text
L1  월별 급식카드 결제 건수   n_t
L2  월별 급식카드 비중        s_t = n_t / (그 달 전체 결제 건수)   ← 플랫폼 성장 효과 제거
L3  월별 확산 지표            shops_t (급식결제 발생 가맹점 수)
                              dongs_t (급식결제 발생 행정동 수)
                              custs_t (급식결제 고유 고객 수)
```

**`s_t`가 주 계열이다.** `n_t`만 보면 대구로 자체의 성장·쇠퇴와 급식카드 도입이 섞인다.

**탐지 절차**

1. **도입 시점**: `FIRST_YM` = `n_t > 0`인 최초 월. 그 이전 구간은 분석에서 제외.
2. **전환 구간 식별**: `s_t`에 **PELT 변화점 탐지**(`ruptures`, model="l2" 또는 "rbf", BIC 계열 페널티). 42개 관측치이므로 변화점 최대 3개, 최소 세그먼트 길이 6개월을 강제.
3. **사전 후보 시점과 대조**: 대구시·보건복지부의 아동급식 관련 공고(배달앱 결제 허용, 단가 개정, 지원 대상 확대)로 후보 시점을 미리 목록화하고, 탐지된 변화점이 그 근처인지 확인 `[VERIFY — 공개 자료 조사]`. 일치하면 **정책 이벤트로 해석**할 수 있고, 이는 H5의 이벤트 스터디와 직결된다.
4. **후보 시점 Chow 검정** — `s_t`를 시간 추세에 회귀하고 전후 계수 동일성 검정.
5. **확산 vs 수준 이동 구분**: `s_t`는 뛰었는데 `shops_t`·`dongs_t`가 완만하면 **기존 사용자의 사용 빈도 증가**, 함께 뛰면 **공급·대상 확대**. 정책 해석이 완전히 달라지므로 반드시 분리한다.
6. **계절성 점검**: 방학(1~2월, 7~8월)에 수요가 달라질 수 있다. `s_t`를 월 더미로 회귀해 계절 성분을 분리하고, 변화점 탐지를 계절 조정 계열에서도 반복한다.

**분석 기간 확정 규칙**: 마지막 변화점 이후 구간을 **주 분석 기간**으로 삼고, 이전 구간은 별도 절에서 "도입·확산기"로 기술한다. 주 분석 기간이 12개월 미만이면 §4.2의 `MONTHS` 조건에 따라 1차 fallback으로 내려간다.

**대구로 `DONG_NM` → 행정동코드 매핑 절차**

1. **정규화**: 공백·괄호 제거, 중점 문자 통일(`·` `‧` `ㆍ`), "제1동"↔"1동", "1.2동"↔"1·2동", 한자·약칭 처리.
2. **자동 매칭**: 정규화 명칭 완전일치 → 부분일치 → 편집거리(Levenshtein ≤ 2) 순.
3. **수작업 전수 검증** — **대구 행정동은 140여 개 규모**라 전수 육안 확인이 현실적이다 `[VERIFY — 정확한 개수는 데이터로]`. 자동 매칭 실패·모호 건은 전부 손으로 확정하고 `match_method='manual'`로 표시한다.
4. **행정구역 변경 이력 반영**
   - **군위군의 2023-07-01 대구 편입** — 데이터 기간 중간에 대구의 지역 범위가 바뀐다. 편입 전후로 분모(대구 전체)가 달라지므로 **시계열 비교는 군위 제외 기준**으로 하고 군위는 별도 절에서 다룬다 `[VERIFY_WITH_DATA — 군위 dong이 실제로 등장하는지]`.
   - 행정동 통폐합 이력은 `valid_from`/`valid_to`로 표현하고, 분석은 **최근 시점 기준으로 통일**하되 통폐합된 동은 합쳐서 다룬다.
5. **매칭률 보고**: 자동 일치율, 수작업 확정 건수, 최종 미매칭 건수와 그 가맹점 수·주문 비중. **미매칭 0을 목표**로 하고, 남으면 규모를 명시한다.

#### 행정동 ↔ 법정동 (신한카드 결합) — 2경로 전략

#### 신한카드로만 가능해지는 지표 3종

업종 컬럼 부재(§0-A)를 메우면서 동시에 **새로운 결과**를 만드는 지표들이다.

1. **플랫폼 침투율** `P(d) = 대구로 가맹점 수(d) / SHC001 전체 음식 가맹점 수(d)`
   → **"대구로가 얇게 깔린 동"과 "가맹점 자체가 없는 동"을 분리**한다. 사각지대의 원인 진단에 직결.
2. **급식 수용률** `A(d) = 급식 가능 가맹점 수(d) / SHC001 전체 음식 가맹점 수(d)`
   → **가맹점 모집 잠재력**. 분모가 모집 가능한 총 풀이므로, 목표 커버리지 달성에 몇 곳을 더 모집해야 하는지가 바로 나온다. §6.4 우선순위 표의 핵심 컬럼.
3. **수요-공급 시간 정합** `ρ_demand(d,h) = S*_급식(d,h) / SHC002 결제건수(d, h, 음식업종)`
   → **"수요는 있는데 급식으로는 못 쓰는 시간대"** 를 정확히 짚는다. 이 연구의 가장 정책적인 산출물.

대상: `INS_001` 611MB / `INS_006` 529MB / `INS_003` 259MB (+ `SHC002` **3.13GB**). 행 수 기준 700만~880만 행 × 3.

## 7. 윤리 · 주장 범위 점검

### 7.1 주장 범위 한정 — 기획서용 확정 문구

**핵심 제약** `[CONFIRMED]`: `PAY_GBN='아동급식카드'`는 **결제 수단**을 뜻할 뿐 결제자가 아동임을 뜻하지 않는다. 보호자 대리 결제가 가능하고, `INS_005.BR_DT`는 **계정 명의자**의 연령대다. 배달 목적지도 관측되지 않는다.

아래 문구를 기획서 "연구의 범위" 절과 결론 앞에 **그대로** 배치한다.

> **[범위 문구 1 — 관측 대상의 정의]**
> 본 연구가 관측하는 것은 아동의 식생활이 아니라, **아동급식 지원 수단이 공공배달앱에서 사용되는 시공간과 그 제약**이다. 데이터는 결제 수단이 '아동급식카드'인 거래를 식별할 수 있을 뿐이며, 그 거래의 실제 이용자가 아동인지 보호자인지, 또는 누구를 위한 것인지는 관측되지 않는다. 따라서 본 연구는 개인 단위의 아동 특성·식습관·영양 상태에 대해 어떠한 주장도 하지 않는다.

> **[범위 문구 2 — 계정 연령대의 해석]**
> 고객 연령대(`BR_DT`)는 계정 명의자 기준이며 실제 이용자와 일치한다는 보장이 없다. 본 연구에서 연령대는 **통계적 통제변수로만** 사용하며, 연령대별 아동 이용 실태를 추정하는 데 사용하지 않는다.

> **[범위 문구 3 — 커버리지의 하한 성격]**
> 본 연구가 측정하는 접근성은 **공공배달앱 '대구로' 경로에 한정된 접근성**이다. 오프라인 급식카드 가맹점에서의 직접 결제, 타 배달 플랫폼, 편의점·급식소 등 다른 경로는 관측되지 않는다. 따라서 본 연구의 커버리지 지표는 전체 급식 지원 접근성의 **하한(lower bound)** 이며, 특정 동의 지표가 낮다는 것이 곧 그 동 아동의 급식 접근성이 낮음을 뜻하지 않는다. 다만 **이동이 어려운 시간대·기상 조건·보호자 부재 상황에서 배달 경로의 중요성이 커진다**는 점에서, 배달 경로의 공백은 그 자체로 정책적 의미를 갖는다.

> **[범위 문구 4 — 가맹점 지표의 의미]**
> `CHILD_ABLE_YN='Y'`는 해당 가맹점이 **대구로 플랫폼에서 아동급식카드 결제를 수용하도록 등록**되어 있음을 뜻한다. 이는 지자체가 지정한 오프라인 급식 가맹점 목록과 일치하지 않을 수 있으며, 등록되어 있다는 사실이 해당 시간에 영업 중임을 뜻하지도 않는다. 본 연구는 영업 여부를 관측할 수 없어 **실제 주문 발생 이력으로 대리 관측**하였고, 이 대리값은 "닫혀 있음"과 "열려 있으나 주문이 없음"을 구분하지 못한다.

> **[범위 문구 5 — 인과 주장의 한계]**
> 배차·배달 결과에 대한 분석은 가맹점 고정효과와 성향점수 매칭으로 관측 가능한 선택 편의를 완화하였으나, **업종 정보가 데이터에 존재하지 않아 업종 차이를 직접 통제하지 못했다.** 매개분해는 순차적 무시가능성을 요구하며, 본 연구의 배달팁 경로 분해는 **인과적 매개효과가 아니라 관측 가능한 가격 경로를 통한 기술적 분해**로 해석해야 한다.

### 7.2 최소 집계 단위 기준 (재식별 위험 통제)

급식카드 이용자는 소수 집단이며, 세분화된 셀에서는 **특정 가맹점 또는 특정 이용자가 사실상 지목**될 수 있다. 다음 규칙을 **모든 출력물(표·그림·지도·반출물)에 예외 없이 적용**한다.

| # | 규칙 | 임계 | 근거 |
|---|---|---|---|
| **R-1** | 어떤 셀도 **관측 건수 5건 미만이면 공표하지 않는다** | `n ≥ 5` | 통계 공표의 관행적 최소 셀 크기 |
| **R-2** | 급식카드 관련 셀은 **고유 가맹점 3개 미만이면 공표하지 않는다** | `n_shop ≥ 3` | 셀이 사실상 특정 가맹점 하나를 가리키는 것을 방지 |
| **R-3** | 급식카드 관련 셀은 **고유 고객 5명 미만이면 공표하지 않는다** | `n_cust ≥ 5` | 개인 재식별 방지 |
| **R-4** | **보완 억제(secondary suppression)** — 억제된 셀이 행·열 합계로부터 역산되지 않도록 같은 행/열에서 추가 셀을 억제 | 자동 알고리즘 | 억제의 무력화 방지 |
| **R-5** | **공간 최소 단위는 행정동**이다. 그보다 세분화된 단위(가맹점 위치·좌표·상권)로 지도를 그리지 않는다 | 행정동 | 데이터 자체가 동 단위이며 그 아래로 내려갈 근거가 없다 |
| **R-6** | **개별 가맹점을 식별 가능한 형태로 공표하지 않는다.** 순위표·이상치 라벨은 행정동까지만 | — | `SHOP_ID`는 가명이나 "OO동에서 급식 주문이 가장 많은 가맹점"은 실명 특정으로 이어질 수 있다 |

| **R-8** | 공표용 시간 축은 **3시간 구간**을 기본으로 한다. 시간 단위(24)는 **대구 전체 집계**에서만 | 3시간 | 동×시간 조합에서 셀이 얇아지는 것을 사전 방지 |
| **R-9** | 반출물에 **원자료·개별 레코드·가명 ID를 포함하지 않는다.** 집계표·모형 계수·그림만 반출 | — | 안심구역 반출 원칙 `[ASK — 실제 절차 확인 필요]` |
| **R-10** | `CUST_ID`는 **통제·군집 표준오차·재구매 지표 산출에만** 사용하고, 고객 프로파일링·개인 궤적 서술은 하지 않는다 | — | §7.1 범위 문구 1·2와 정합 |

**운용 방식**

- 억제 규칙을 파이프라인의 **공표 직전 단계 함수 하나**(`suppress(df, n_min=5, shop_min=3, cust_min=5)`)로 구현해 모든 출력이 반드시 통과하게 한다. **사람이 기억해서 지키는 방식은 쓰지 않는다.**
- **억제된 셀의 수와 비율을 부록 C에 보고**한다. 억제 사실을 밝히는 것이 신뢰를 만든다.
- 지도에서 억제 셀은 회색 + 범례 "집계 기준 미달"로 표시한다.
- §4.2의 게이트 임계값(`N_SHOP ≥ 500` 등)은 이 억제 규칙과 정합하도록 설정돼 있다 — 가맹점이 적으면 R-2에 걸려 어차피 공표할 수 없다.

### 7.3 그 밖의 윤리 점검

- **낙인 효과**: "사각지대"로 지목된 행정동이 부정적으로 표상될 위험. → 서술을 **"인프라 배치의 문제"** 로 일관되게 프레이밍하고, 지도 제목도 "결핍 지역"이 아니라 **"가맹점 확충 우선 지역"** 으로 한다(같은 정보, 다른 프레임).
- **가맹점에 대한 함의**: H4에서 급식 가맹점의 폐업 위험이 높게 나오더라도 "급식 참여가 폐업을 유발한다"고 해석하지 않는다. 관측되지 않은 업종·입지 차이가 남아 있다(§7.1 범위 문구 5).
- **정책 제언의 수위**: 본 연구는 접근성 진단이며, 예산 배분·단가 결정에 대한 규범적 주장은 하지 않는다. 제언은 **"어디에·어느 업종에서 가맹점을 모집할 것인가"** 라는 집행 수준에 한정한다.
- **데이터 출처 표기**: 인성데이타㈜(대구로), 신한카드, KCB의 데이터 제공 사실을 산출물마다 명기한다.
